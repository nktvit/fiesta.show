# **StreamFiesta**

Angular 20 (standalone components, zone-based, Tailwind 3) movie/TV streaming
site, deployed on Vercel. `main` is the **production** branch — merging to it
deploys to fiesta.show.

## Setup

```bash
# Best option is bun (fewer dependency issues)
bun install
# or
npm install

# Start the dev server (http://localhost:4200)
npm start
```

`src/environments/environment.ts` is gitignored and generated by
`scripts/set-env.js` on `prebuild` (only `OMDB_API_KEY`, from the environment;
**no TMDB key ever reaches the browser**). The script skips generation if the
file already exists, so delete it to regenerate after changing the key.

### Dev workflow (API harness)

Every TMDB call goes through `/api/tmdb` (and `/api/movie`, `/api/omdb`,
`/api/suggestions`), exactly like production. `ng serve` proxies those paths
(`src/proxy.conf.json`) to a small local harness that runs the real `api/*.js`
handlers, so dev serves the same code as production. Run both, in two terminals:

```bash
# 1. API harness on :3999 (reads TMDB_API_KEY / OMDB_API_KEY from the shell,
#    ./.env or ./.env.local; PORT=... to change the port)
node tools/fiesta-proxy/local-test-server.mjs

# 2. the app
npm start
```

Without the harness the TMDB lists render empty (the proxy gets ECONNREFUSED).
To use another port, copy `src/proxy.conf.json`, change the targets and pass
`ng serve --proxy-config <copy>`.

## Scripts

| Command | What it does |
|---|---|
| `npm start` | dev server on :4200 |
| `npm run build` | builds `tv/` then the Angular app |
| `npm run watch` | development build, watched |
| `npm test` | Karma unit tests (add `--watch=false --browsers=ChromeHeadless` for CI) |
| `npm run eval:moderation` | comment-moderation evals |

`npm test` needs no API keys: `movie.service.spec.ts` pins the environment
itself. The season rules in `lib/seasons.js` have a plain Node test:
`node --test tools/fiesta-proxy/seasons.test.mjs`.

## Serverless functions

`api/` holds the Vercel functions (`tmdb`, `omdb`, `movie`, `stream`, `subs`,
`music`, `likes`, `comments`, `suggestions`). `ng serve` does not run them; the
harness above mounts `tmdb`, `movie`, `omdb`, `suggestions`, `stream`, `subs`
and `music`. `likes` and `comments` (Upstash Redis) are not mounted, so they
only work on a deployment.
